## 3. 数据库与账号隔离

- 单个 PostgreSQL 17.2 实例（Compose 内 `postgres` 服务），通过
  `deploy/compose/postgres-init/01-init-databases.sh` 在容器首次初始化时创建：
  - `iam_db`（属主 `iam_app`）
  - `audit_db`（属主 `audit_app`）
- 两个账号互不relate，`REVOKE ALL ON DATABASE ... FROM PUBLIC` 后只对各自
  数据库授权，满足"禁止跨服务直接读表"的约束。
- 应用服务只使用各自专属账号连接，超级用户 `POSTGRES_SUPERUSER` 仅用于初始化脚本。
- **重要**：`deploy/compose/postgres-init/01-init-databases.sh` 必须保留可执行位
  (`chmod +x`)，否则 Postgres 官方镜像的 entrypoint 会以
  `bad interpreter: Permission denied` 静默失败并跳过整个初始化脚本
  （已实测踩坑并修复；git 若被配置为不保留可执行位需注意）。

## 4. 端口分配（本地开发）

| 用途 | 端口 | 说明 |
| --- | --- | --- |
| 网关（Traefik，唯一对外入口） | `GATEWAY_HTTP_PORT`，默认 `8080` | 本地只用 HTTP；生产改用 443，见 `deploy/gateway/traefik.prod.yml.example` |
| PostgreSQL（宿主机映射，开发便利用） | `POSTGRES_HOST_PORT`，默认 `5433` | 默认避开 5432，防止和本机已运行的 PostgreSQL 冲突；容器间通信始终用内部 5432 |

| audit-service | 容器内部 `8002`，不映射宿主机 | 同上 |
| frontend（Nginx） | 容器内部 `80`，不映射宿主机 | 同上，经网关访问 |
| 前端本地开发（`pnpm dev`，不经 Compose） | `5173` | Vite 默认端口，代理 `/api` 到 `VITE_GATEWAY_TARGET`（默认 `http://localhost:8080`） |

## 5. 网关路由实现方式：文件 Provider，而非 Docker Provider

最初按惯例用 Traefik 的 Docker Provider（容器 label 驱动路由），实测发现
**Docker Desktop for Mac 上 Traefik 容器无法通过挂载的 `/var/run/docker.sock`
连接 Docker API**（`Error response from daemon: ""`，持续重试失败），这是
Docker Desktop 的已知 socket 权限限制，不是配置错误。

改为 **Traefik 文件 Provider**：`deploy/gateway/traefik.yml`（静态配置）+
`deploy/gateway/dynamic.yml`（路由/服务定义，显式列出四个上游）。优点：
- 不需要把 `/var/run/docker.sock` 挂进网关容器（减少攻击面）。
- 路由集合本期是固定的（iam-service 两个前缀、audit-service 一个前缀、
  一个 404 兜底、前端一个兜底），文件方式更直观、可 diff review。
- 跨 Windows/Mac/Linux Docker Desktop 行为一致，不依赖 socket 转发细节。

路由优先级设计（数值越大越先匹配）：

| 优先级 | 路由 | 目标 |
| --- | --- | --- |
| 100 | `/api/v1/auth`、`/api/v1/system` | iam-service |
| 100 | `/api/v1/audit` | audit-service |
| 50 | `/api/v1`（兜底） | `api-fallback`（Nginx，统一返回 JSON 404） |
| 1 | `/`（兜底） | frontend（Vue SPA） |

已实测验证：`/api/v1/policy/*` 等未接入前缀被 `api-fallback` 拦截返回
`{"code":"RESOURCE_NOT_FOUND",...}`，不会被前端 SPA 兜底路由捕获返回 200 的 HTML。
`/health/*`、`/internal/*` 未声明任何路由，网关层完全不可达（落到前端兜底，
返回前端 HTML 而不是任何后端信息）。

## 6. 前端构建工具链的坑

- 本机全局 `pnpm` 版本是 12.4.1（比 npm 官方稳定版更新，`pnpm-lock.yaml` 用
  `lockfileVersion: '9.0'`，其 `pnpm approve-builds` 结果落在 **新格式**
  `pnpm-workspace.yaml` 的 `allowBuilds` 字段，而不是旧的 `package.json`
  `"pnpm"` 字段（新版 pnpm 已不读取后者，仅打印 WARN）。
- Docker 构建阶段必须安装 **同一 major 版本的 pnpm**（`npm install -g
  pnpm@12.4.1`），否则旧版 pnpm 读取新格式 `pnpm-workspace.yaml` 会报
  `packages field missing or empty` 这种误导性错误。`pnpm-workspace.yaml`
  已提交仓库，Dockerfile 在执行 `pnpm install` 前必须先 `COPY` 该文件。
- Corepack 的 `corepack prepare pnpm@9 --activate` 在当前 Node 22 镜像上会因为
  签名校验（`Cannot find matching keyid`）失败，改为直接 `npm install -g
  pnpm@<版本>`，不依赖 Corepack。
- `@vue/tsconfig` 0.7.0 只提供 `tsconfig.json` / `tsconfig.dom.json` /
  `tsconfig.lib.json`，**没有** `tsconfig.node.json`；`vite.config.ts` 的
  Node 侧 tsconfig 需要 `extends: "@vue/tsconfig/tsconfig.json"`（而不是网上
  一些过时教程写的 `tsconfig.node.json`）。
- 根目录 `.dockerignore` 必须排除 `**/node_modules/`、`frontend/dist/`，否则
  `COPY frontend/ ./` 会把宿主机的 `node_modules`（可能由不同 pnpm 版本生成）
  拷进镜像，污染容器内刚装好的依赖树。

## 7. 统一响应/异常格式

`packages/platform-common/platform_common/responses.py`、`errors.py` 严格按照
《中台系统公共基础框架设计.md》第 11.1 节的 JSON 形状实现：

```json
{"code": "OK", "message": "success", "data": {...}, "request_id": "..."}
```

错误响应通过统一异常处理器覆盖：`ApiError` 子类（业务异常）、
`RequestValidationError`（FastAPI 422 校验错误）、`StarletteHTTPException`
（包含 FastAPI 默认的 404 等）、未捕获 `Exception`（500，不泄露堆栈）。
`X-Request-Id` 请求头与响应体 `request_id` 字段保证同一个值，便于跨服务
日志关联；已通过 6 个真实 HTTP 测试验证（`packages/platform-common/tests/`）。

Python 3.12 起支持的 PEP 695 泛型语法（`class Page[T](BaseModel)`）已用于
`ApiResponse[T]` / `Page[T]`，比 `Generic[T]` 写法更符合 `ruff` 的 `UP046/UP047`
建议。

## 8. Alembic 迁移环境与配置解耦

`app/core/database.py`（引擎/会话创建，依赖完整 `Settings`，包括与迁移无关的
Redis 配置）与 `app/core/orm_base.py`（只放 `DeclarativeBase`，无外部依赖）拆开。
`migrations/env.py` 只导入 `orm_base.Base`，避免执行 `alembic revision`/`upgrade`
时因为缺少不相关的环境变量（如 iam-service 的 `IAM_REDIS_URL`）而报错。
连接串固定从 `IAM_DATABASE_URL` / `AUDIT_DATABASE_URL` 环境变量读取，不写入
`alembic.ini`。已实测：两个服务从空库执行 `alembic upgrade head` 成功，
重复执行幂等（无变更）。

## 10. 待后续阶段处理的已知事项

- 前端生产构建产物中 `index-*.js` 约 1MB（gzip 后 344KB），主要是整包引入
  Element Plus；P4 阶段接入真实页面时应改为按需引入组件，控制包体积。
- Traefik 文件 Provider 默认只在启动时加载一次 `dynamic.yml`；如果后续需要
  免重启热加载路由（例如接入业务服务），需要确认 Traefik 3.2 file provider
  的 watch 行为或改回 Docker Provider 并解决 Mac Docker Desktop 的 socket
  权限问题（可能需要 Docker Desktop 的 "Allow the default Docker socket to
  be used" 设置，或改用 TCP Provider）。
- 沙盒执行环境中观察到：即使 `docker inspect` 显示 `HostConfig.PortBindings`
  配置正确，某些情况下宿主机端口实际未监听（`NetworkSettings.Ports` 为空）。
  这被判断为当前工具沙盒的网络限制，而非项目配置问题（`docker compose
  config` 输出、容器内部网络访问、经网关的验证均已确认正确）；实际用户机器
  上直接运行 `make dev-up` 不应有此问题，但如遇到宿主机端口访问不到容器，
  可先确认是否是本地网络代理/沙盒环境的限制。
