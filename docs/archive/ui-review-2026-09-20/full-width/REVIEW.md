# 默认全字段与全宽表格修订

2026-09-20。用户否定了上版核心列默认与窄表格的视觉效果，并明确确认：默认全部字段，不想看某些字段的用户自行在列设置中隐藏。

## 本次变化

- 六个业务列表默认完整字段集合，保留列设置、显示全部与恢复默认。旧版系统核心列偏好迁移为全部；已有自定义列选择保留。
- 表格外框铺满结果区，与操作栏和分页对齐。取消表格整体宽度上限；短字段固定宽，长文本分享余量，超宽时局部横向滚动。
- 六个业务表数据行44px，长内容单行省略，悬停或详情可看全文。不再为每行长标题撑高整张表。
- 收紧标题、筛选和工具栏间距，1280px下常用筛选与按钮同一行；单字段筛选的查询按钮紧邻输入框。
- 长表头继续使用简洁显示名称，完整业务名称在提示/详情保留。字段值、API及Excel映射不变。

## 实际验证

- 用户实际入口 `http://localhost:8080` 已通过Docker重新构建并替换frontend容器。
- 六个业务列表默认数量均与完整字段集合一致。信源隐藏省份和地市：16→14列，刷新仍14列；恢复默认返回16列。
- 行业场景水平滚动至末尾，DOM实测scrollLeft和最大值均为6004px；查看/编辑仍在右侧可达。
- 1280、1920、2560桌面及390px手机检查；桌面表格外框与工具栏同宽，documentWidth等于视口宽度。宽屏与窄桌面数据行均44px；手机未出现整页横向溢出。
- 前端类型检查、Lint、18项单测及Docker生产构建通过；Premium strict静态审查0项问题；git diff --check通过。
- 构建保留原有主包超过500kB提示。替换构建期间旧标签曾请求过期资源，刷新最终构建后导航恢复；未把该瞬时部署问题当作列设置问题。

本轮验证聚焦显示列、表格布局、导航、只读详情和手机适配，没有重复提交真实业务编辑或上传。此前写入E2E及官方designmd lint的验证边界继续见上级实施记录。截图是本轮实现证据，不等于用户已经确认视觉满意。

现行复用规则已同步DESIGN.md、UX-CONTRACT.md及UI开发规范；旧column-widths报告已标明被本轮替代。
