## 1. 如何使用

将本文件与《业务数据运营平台公共基础框架设计.md》一起放入项目的 `docs/` 目录。项目已有代码时保留现有文件，不重新生成覆盖。下文所有路径均相对于项目根目录。

先把第 3 节“启动提示词”复制给 Cursor。按 P0～P6 顺序开发，可以每次执行一个阶段；每阶段必须实现、验证并更新进度文件，不能只回复方案。

本文将架构文档中的阶段进一步拆成可执行任务。审计 Outbox 在 P2 提前实现写入基础，P5 再完成消费与查询，避免后期改造所有事务。其余服务边界、权限规则遵循架构文档。

## 2. 不可越过的开发范围

### 2.1 本期需要开发

- 用户管理：创建、查询、编辑、禁用、重置密码、强制下线。
- 登录、退出、刷新会话、首次登录强制改密、本人修改密码。
- 角色管理、用户角色分配、模块权限分配。
- NONE / READ / FULL 三档权限，前端菜单、路由、按钮与后端接口校验。
- 登录日志、操作日志、Outbox 可靠投递和日志查询。
- Vue 管理端布局、系统管理页面、错误页面。
- 公共服务、网关、数据库迁移、容器部署、配置、测试及运行文档。

### 2.2 本期严禁提前开发

- 不设计、不创建任何政策、客户、招投标、码表业务表或迁移。
- 不实现爬虫、信源抓取、政策解读、标签逻辑、码表 CRUD 或其他业务 API。
- 不生成这些业务模块的演示页面、模拟业务数据、占位 HTTP 接口。
- 不根据菜单名称自行推断字段、关联关系、状态、工作流和业务操作。
- 不提供用户注册，不引入多租户、部门数据权限、审批流、文件服务、微前端或额外中间件。

只允许在业务目录中保留空目录或 `.gitkeep`；目录名称与未发布的权限资源元数据可以登记。公共用户、角色、权限、会话及审计表允许按照架构文档实现。

### 2.3 已知业务目录

```text

├── 爬虫监测
├── 政策解读列表
└── 政策基础标签表
```

这些是目录名称，不是数据库设计。政策、码表各对应一个未来业务服务，其子模块不单独拆微服务。客户、招投标不自创子模块。

## 4. 全程实现约定

### 4.1 服务与运行单元

首期运行 `frontend`、`gateway`、`iam-service`、`iam-worker`、`audit-service`、`postgres`、`redis`。Worker 与 IAM 共用镜像但使用不同进程命令。P1 可先不启动尚未实现的 Worker，P5 必须加入。

共享包 `packages/platform-common/` 只放协议、异常、鉴权客户端、日志与 Outbox 工具，不共享服务 ORM 模型。独立服务可共用一台 PostgreSQL，但使用不同数据库与账号。

### 4.2 权限不变量

- 多个启用角色取最大授权等级：NONE < READ < FULL，NONE 不是显式拒绝。
- 父节点选择只批量更新当前已发布叶子资源，不对未来新增资源自动继承。
- 未发布业务只显示在权限配置树的禁用区域，不出现在正常业务导航，也不能授权。
- `system.users:FULL` 不等于角色分配权限；`system.roles:FULL` 不等于角色授权权限。
- `system.permissions:FULL` 首期仅超级管理员具有，普通角色不能获得它。
- 超级管理员也必须经过账号状态、会话、强制改密及资源发布状态检查；不能访问不存在或未登记的接口。
- 首期不缓存“允许访问”结果，每次判定读取当前权威状态。
- 对最后一个有效超级管理员的保护必须经得住并发操作；不能只在前端提示。

### 4.3 接口与状态

接口清单以架构文档第 11 节为准，前缀 `/api/v1`；内部接口 `/internal/v1` 不由网关公开。

必须统一正常响应与错误响应、请求 ID、分页、排序白名单、真实 HTTP 状态码。FastAPI 的校验错误和未捕获异常也必须纳入统一格式。204 不返回 JSON 包装体。

建立接口安全分类：公开认证接口、受限会话接口、普通登录接口、资源授权接口、内部服务接口。每个路由必须显式声明分类，以路由遍历测试发现遗漏；公开白名单保持最小。

### 4.4 项目命令约定

实现统一任务入口，推荐以下名称；P6 后这些命令均已落地：

| 命令 | 行为 |
| --- | --- |
| `make bootstrap` | 检查环境、安装锁定依赖，不覆盖真实配置 |
| `make dev-up` / `make dev-down` | 启停本地开发环境；down 不删除数据卷 |
| `make migrate` | 独立运行 IAM 与审计库迁移 |
| `make seed` | 幂等同步公共资源、动作、基础菜单与内置角色 |
| `make admin-create` | 安全交互式创建初始管理员，不覆盖已存在账户 |
| `make check` | Python 静态检查、前端类型检查及构建 |
| `make test-unit` | 单元测试 |
| `make test-integration` | 独立测试库上的真实依赖集成测试 |
| `make test-e2e` | 浏览器端关键流程测试 |
| `make smoke` | 经网关执行公共功能冒烟验证 |

测试账号可由测试夹具在隔离环境创建，但不能被生产初始化脚本使用。清库必须校验测试环境和数据库名称，不允许默认连接开发库或生产库。

## 8. P3：权限引擎与公共管理 API

**前置条件：** P2 认证、模型与会话验证通过。

任务：

- [x] 实现角色权限聚合、发布状态检查、资源动作登记和未知动作拒绝。

- [x] 明确请求 DTO 字段白名单，禁止用户编辑接口通过额外字段修改角色或超级管理员状态。
- [x] 实现用户禁用、密码重置和强制下线时撤销会话。
- [x] 实现用户及角色授权版本冲突 409，替换授权在一个事务内完成。
- [x] 实现超级管理员保护、系统权限分配边界及最后管理员并发保护。
- [x] 所有已实现管理写操作接入同事务 Outbox，拒绝及失败操作独立记录。
- [x] 实现 `/auth/permissions`、本人有效资源等级及可见菜单。
- [x] 增加路由分类覆盖测试，防止新增接口忘记鉴权。

**验证与验收：**

- READ 可读不可写；FULL 只能操作其资源；NONE 全部拒绝。
- NONE + READ = READ，READ + FULL = FULL，禁用角色不参与聚合。
- 普通用户管理员不能分配角色、不能修改或重置超级管理员。
- 未发布资源不能授权；未知资源及动作拒绝，包括超级管理员请求。
- 撤销权限后下一次请求被拒；禁用用户后未过期 JWT 也被拒。
- 两个并发操作不能移除最后一个有效超级管理员。
- 两次基于相同版本的授权编辑只允许一次成功，另一次返回 409。
- 通过真实 HTTP 调用证明后端限制，不只验证菜单显隐。

**无业务测试方式：** 用公共管理资源测试权限；需要跨模块、POST 只读等情况时，在测试应用内注册专用资源及无业务数据的测试路由。测试路由不得进入开发或生产运行镜像的路由表。

**验证与验收：**

- 管理写操作与 Outbox 同时成功或同时回滚。
- 审计服务停机后管理操作可成功，事件留在 Outbox；恢复后最终补齐。
- 接收成功但 Worker 未标记时崩溃，重放后审计表仍只有一条事件。
- 多 Worker 不丢任务；租约过期任务可重新认领，重复提交幂等。
- 超阈值失败可观察且可重放，事件不被静默丢弃。
- 查询审计需授权，浏览器不能访问内部写入接口。
- 密码、刷新令牌、Cookie、私钥不出现在审计、访问日志和异常日志中。
