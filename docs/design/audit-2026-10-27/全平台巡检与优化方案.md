# 全平台巡检与优化方案

2026-10-27。线上 `https://1.119.196.77` 只读走查 + 四组代码审查（政策服务、AI 服务、IAM / 审计 / 码表 / 公共包、前端）。
标「已核」的是我在代码或线上亲自核对过的；标「审查员实测」的是审查员本地复现过、我只看了代码走向；标「待核实」的只是怀疑。

## 巡检方法

- 22 个页面逐个打开（1440、1024、390 三档宽度），打开详情抽屉、执行记录、操作日志详情、用户编辑抽屉，做关键词筛选和重置。全程没有控制台报错、没有 4xx / 5xx 请求、没有整页横向溢出；手机宽度表格局部横滚，符合约定。没有保存、运行、导出任何东西。
- 各服务单测在本机全部通过（policy 262、ai 138、iam 199、audit 37、codebook 77、platform-common 173、前端 411）。
- 线上随机取 3 条源政策，量了正文读取耗时（见第四节）。

## 二、一般：功能不对、误导用户

### AI 服务
- 看门狗协程无异常保护（已核，`batch_execute.py:200-209`）：库连接抖一下它就静默死掉 → 心跳停 → 90 秒后被标「中断」而 worker 仍在花钱；停止按钮失效；跑完后全部成功也被记成「执行失败」。`_load` 在心跳开始前解析 Excel、读回 CSV，大任务重跑超 90 秒同样被误判。改法：`_watch` 内 try/except 继续循环，`_load` 前先写一次心跳。
- 定时任务的批次在页面上能「重跑」（已核，`batch_runs.py:_can_retry` 不看 `source`，`BatchHistory.vue:209`）：到了费用上限的打标批次点重跑 → 带着历史费用第一行就触顶，在途 20 行照样计费，结果没人消费。改法：`pipeline` 来源 `can_retry=false`，后端拒绝。
- 上线版本用的模型被停用后，批量任务报「模型已停用，请换一个模型」，页面上换不了（`asking.py:71`）。改成「上线版本用的模型已停用，请改模板模型后重新上线」。
- 重跑的费用记到原发起日（`repositories/billing.py:41,53` 按 `created_at`）：几天后重跑，账单回头改早先那天的数。
- 大任务内存：所有行的完整提示词（含码表全文）一次拼好、跑完前一直持有，结果 Excel 用普通 Workbook（`batch_execute.py:233`、`batch_output.py:152`）。1 万行 × 3.8 万字约 760MB，10 万行会把 ai-worker 打到 OOM，所有在跑任务一起中断。改法：按需拼提示词、写完 CSV 不再持有、结果用 `xlsx_writer`。

### 政策服务
- 超长单元格导入直接 500（`sources.py:270`、`base_tags.py:171`、`interpretations.py:207` 不查长度）：网站名称超 255、政策层级超 64 等 → DataError → 用户只看到「服务器内部错误」，整份退回不知道哪行。改法：按列宽校验，写进校验说明。
- 「重新判断类型」清空人工填的穿透三列和备注（`rules.py:228-235` 固定写空串，`tagging.py:60` force 覆盖全部字段），前端提示只说覆盖类型。改法：force 只改类型、是否解读和 AI 备注段。
- 爬虫状态不校验取值（`schemas.py:18` 收任意字符串），统计只认 已爬 / 未爬 / 异常：出现「暂停」等值时分省透视三列之和 ≠ 合计。改法：后端固定集合。
- 信源导入分配编码 O(n×m) 且在事件循环里跑（`sources.py:292`、`region.py:79`）：2 万行库 + 2 千行无编码文件约 4 千万次正则，整个服务挂几十秒。改法：按前缀预先求最大序号。
- 导入查重整表读进内存（`base_tags.py:194`、`interpretations.py:243`）：AI 持续写入到几百万行后每次导入拉几百 MB。改法：按文件内的键分片 `IN (...)`。
- 中断批次的花费不计入当日上限（`pipeline.py:76、99-101`）。
- 待核实：爬虫增量同步补录多天时可能永远超时（1800 秒，单日最长 7 分钟，水位只在成功后写）。

### IAM
- 登录按响应时间可枚举用户名（`auth_service.py:39`：用户不存在时不跑 Argon2）。改法：用户为空时对固定假哈希校验一次。
- IAM 返回 404/422 等非预期响应时被当「无权限」（`authz.py:88-98`）：部署错路由时用户看到的是权限问题，排障往授权上找。改法：非 200 一律 503。

- 操作日志「动作」列直接显示 `ask`、`publish`、`sync_scenarios`，模块缺 `ai.releases`（已核，`utils/auditLabels.ts`）。
- 权限页「管理包含」露出 `publish`、`sync_scenarios`、`sync`（已核，`permissions/catalog.ts` WRITE_ACTIONS）。

- 页面名不一致（已核）：菜单「政策解读列表」，页面标题和导出文件「政策解读表」；基础标签导出 sheet 叫「政策基础信息表」；信源导出 sheet 叫「网站编码」。
- 「禁用」与「停用」混用：账号用「禁用」（`UserTable.vue:152`、`UserList.vue:276`、`ProfileView.vue:77` 等），角色 / 模型 / 定时任务用「停用」，同一张用户表里两种都有。批量任务「运行中 / 已停止」与任务调度「执行中 / 已取消」也是两套。统一「停用」，状态词两处对齐。
- 模型选择占位「模型：运行时再选」，上线检查却要求模板必须选定模型（`ModelPicker.vue:30` 与 `ReleaseDrawer.vue:47` 矛盾）。改「选择模型（上线前必选）」。

- 解读详情前几项是「政策唯一标识、关联主键、租户标识」这类内部字段，业务内容靠后（你的复核已提）；操作日志摘要里是 UUID，详情「变更」是 JSON。

## 三、建议（安全加固与体验）

- 密码策略只查长度（`11111111` 可过）；HTTPS 未配 HSTS、安全响应头、TLS 最低版本；Postgres 5433 为 Navicat 对公网开放，五个库的超管口令是唯一防线（建议 SSH 隧道或白名单）；用户管理员可重置任何非超管密码后登录成对方。
- 删模板不清样本试跑目录和记录（孤儿文件）；试发 / 对话中途断开不记用量，账单偏少；码表为空时静默照跑、同名重传不算改动；内部 `pipeline_runs.status` 不先纠正中断任务，policy-service 会轮询到自己超时。
- 爬虫监测页、操作日志页自写加载和错误逻辑，没用 `useListLoader`；续期失败退出登录不带 `redirect`；爬虫配置统计换期只能点柱子，键盘无法切换；复制一次性密码失败无提示；`listBaseTags` 类型缺 `ai_status`、`ResourceLevel` 缺 `EXPORT`（运行时无影响）；`config.py:37` 注释「服务进程不连爬虫库」已过时。

## 四、政策正文查看

**现状。** 正文不在平台库里。源库 `csys_policy_info_content` 按源政策 ID 存整页网页源码（1–3 万字源码，提取后 1–3 千字）。打标时 `rules.page_text` 取出可见文字发给模型；平台任何页面都看不到正文。基础标签和解读都带 `source_content_id`（手工录入 / 导入的为空）。

**实测。** 线上随机 3 条：连库加读取一条 0.23 秒，三条一起也是 0.23 秒；提取文字 2–10 毫秒。policy-service 的 HTTP 进程已经连着出站网络，「从数据库取测试数据」就是这样读源库的。

**建议：点开详情时按需取，不进库。**
- 接口：`GET /api/v1/policy/base-tags/{id}/content`、`GET /api/v1/policy/interpretations/{id}/content`，各挂自己的 `list` 档。按行上的 `source_content_id` 读源库，返回提取后的正文（按段落）、标题、原文链接。没有 `source_content_id` 的返回「这条不是从源库打标的，没有正文」；源库连不上返回 503「源库暂时连不上，稍后再试」（和取测试数据同一句）。
- 页面：详情抽屉 `detail-extra` 槽位加「政策正文」一节：默认先显示前十几行，「展开全文」再放开；段落换行、白底；顶部「打开原网页」链接。只渲染文字不渲染 HTML，网页脚本进不来。
- 为什么不存库：几百万行 × 几千字只为了看，要几个 G；按需读 0.2 秒够用；看到的正文和打标发给模型的是同一段（同一个 `page_text`），业务人员核对打标结果时口径一致。
- 可选：同一条 10 分钟内重复点不再读源库（进程内缓存，不落盘）。

## 五、处理顺序

**第一批（半天，行为改动小）**：第一节 1、2、3、4、6；流水线不可重跑；看门狗保护；重新判断类型保留人工列；操作日志 / 权限页 / 「不传」/ 禁用停用 / 页面名文案；回车两次；模型占位文案。

**第二批（1–2 天）**：政策正文查看；导入超长单元格校验；爬虫状态取值校验；解读详情业务字段分组；批量按钮位置；政策类型码表页按基础标签页重组；旧系统导入修复。

**第三批**：大任务内存；导入查重分片；信源编码分配；登录计时；中断批次费用；密码策略 / HSTS / 5433 端口。

## 六、处理结果（2026-10-27 当天）

已改、测完、部署并在线上只读确认：第一节 6 条全部；第二节除下列几条外全部；第三节的密码规则、HSTS / 安全头 / TLS 1.2、鉴权异常 503、登录计时、删模板清样本试跑、内部状态接口先纠正中断、续期跳转、复制失败提示、换期按钮、类型漂移、文案。共 10 个提交（`e859015` … `77a5581`）。

没改的：
- 重跑的费用记到原发起日：改按完成日分摊会把跨天任务也拆开，账单口径要先定。
- 爬虫监测页、操作日志页没换成 `useListLoader`：两页各有自己的加载节奏，改动大于收益，先不动。
- 试发 / 对话中途断开不记用量；码表为空静默照跑、同名重传不算改动；样本试跑停止事件的目标 ID：先记着。
- Postgres 5433 对公网开放：服务器配置，不在代码里改；建议 SSH 隧道或白名单。
- 用户管理员可重置非超管密码后登录成对方：是不是要限制，产品上先定。
- 爬虫增量同步补录多天可能超时：待核实，没动。
