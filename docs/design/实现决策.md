# 实现决策

架构文档没有固定到具体数值、名称的实施细节，以及踩过的坑。只写现行做法，与代码保持一致；
做法变了就直接改对应条目，过时内容删除，不保留历史。日常约定见 [`CLAUDE.md`](../../CLAUDE.md)，
操作步骤见 [`部署与维护`](../guides/部署与维护.md)。

## 1. 运行时与工具链

- Python 服务和 `platform-common` 都 `uv python pin 3.12`，用 uv 管理的 3.12 解释器，不依赖系统
  `python3`。镜像基础 `python:3.12.7-slim-bookworm`，uv 0.12.13 用 pip 从 PyPI 镜像装（不拉 ghcr.io 镜像，国内很慢）。
- `uv.lock` 只锁版本和哈希，记录官方 PyPI 地址，不锁镜像。镜像构建时 `uv export` 出版本清单，从 `PYPI_INDEX` 构建参数指定的源安装（默认腾讯，新服务器实测 17MB/s，阿里云在那台机器上只有 190KB/s）；`uv sync --frozen` 只认锁文件里的地址，所以镜像里不用它。
- 前端 `engines.node >= 20.19.0`；构建镜像 `node:22.12.0-slim`。pnpm 固定 12.4.1，lockfile 9.0。
- 其余镜像：`postgres:17.2-alpine3.21`、`redis:7.4.11-alpine3.21`、`traefik:v3.7.14`、
  `nginx:1.27-alpine3.21`（前端运行时）/ `nginx:1.27-alpine3.20`（api-fallback）。一律具体 patch 版本，
  不用 `latest` 或浮动标签。

## 2. 数据库与账号隔离

- 一个 PostgreSQL 实例，六个库各有专属属主账号：iam、audit、policy、codebook、ai、thinktank。
  tender-service 不连 PostgreSQL，只读外部 MySQL。
  `deploy/compose/postgres-init/01-init-databases.sh` 在首次初始化时建库建账号，并
  `REVOKE ALL ... FROM PUBLIC`，服务间不能互读。已有数据卷不会重跑 init，
  由 `deploy/compose/scripts/provision-*.sh` 补建（`make migrate` 会调用）。
- 该 init 脚本必须保留可执行位，否则 Postgres 镜像 entrypoint 会 `bad interpreter` 静默跳过整个初始化。
- 审计清理账号 `audit_cleanup` 与应用账号分离，见 `CLAUDE.md`「审计走 Outbox」。

### 连接预算与超时

所有服务经 `platform_common.database.create_service_engine` 建引擎，连接池和 PostgreSQL 超时只在这一处设。

| 进程 | 连接池（常驻 + 溢出） | `statement_timeout` | `idle_in_transaction_session_timeout` |
| --- | --- | --- | --- |
| iam-service、audit-service、codebook-service、thinktank-service | 5 + 10 | 60 秒 | 120 秒 |
| policy-service、ai-service（导出、大文件） | 5 + 10 | 300 秒 | 120 秒 |
| iam 的旁路小池（`SideSessionLocal`，iam-service 和 iam-worker 各一份） | 2 + 3，拿不到半秒放弃 | 10 秒 | 30 秒 |
| iam-worker、audit-worker、policy-worker、ai-worker | 5 + 10 | 关（0） | 关（0） |
| audit-worker 的清理账号引擎 | SQLAlchemy 默认 5 + 10 | 不设 | 不设 |

- 预算：10 个用工厂的进程各 15 条，加 iam 两个旁路池 10 条、审计清理 15 条，峰值约 175 条；
  Postgres 设 `max_connections=200`（`docker-compose.yml`），留的余量给迁移、`psql` 和 Navicat。
  新加一个连库的进程就是再加 15 条，加之前先调 `max_connections` 或把新进程的池调小（`DB_POOL_SIZE` / `DB_MAX_OVERFLOW`）。
- 超时只给对外接口的进程：请求卡死的语句、忘了提交的事务到点被 Postgres 断开，不拖住连接池。
  worker 跑的是几分钟到几小时的同步、打标、批量任务和投递，compose 里给它们设
  `DB_STATEMENT_TIMEOUT_MS=0`、`DB_IDLE_IN_TRANSACTION_TIMEOUT_MS=0`（0 = 不限，工厂按「关」处理，不退回默认值）。
  在 worker 容器里跑的 CLI（爬虫回填、`classify_scenarios` 等）沿用同一套环境变量，也不限。
- 接口进程里要等外部系统（MySQL 源库、模型、码表服务）的长操作，**等之前先提交**，别让请求事务空闲着：
  政策基础标签、解读导出读完本库就提交，再逐批去源库读正文（`policy_content.attach_policy_contents`），
  带正文的导出另有更小的行数上限 `POLICY_EXPORT_CONTENT_MAX_ROWS`（默认 2 万）；
  ai-service 的 pipeline 建任务读完模板上线版本就提交，再写几十 MB 的快照；
  爬虫同步读完水位先提交再去源库找受影响日期（它在 worker 里不限时，但持锁连接被断开代价太大，一样先提交）。

## 4. 网关：Traefik 文件 Provider

不用 Docker Provider：Docker Desktop for Mac 上网关容器连不上挂载的 `docker.sock`，
而且文件方式不需要把 socket 挂进网关，路由可直接 diff review。
静态配置 `deploy/gateway/traefik.yml` + 路由 `dynamic.yml`；线上按地址访问的 HTTPS 用
`traefik.https.yml` + `dynamic.https.yml`（`docker-compose.https.yml` 叠加，开启 `watch`）。

| 优先级 | 路由 | 目标 |
| --- | --- | --- |
| 100 | `/api/v1/auth`、`/api/v1/system` | iam-service |
| 100 | `/api/v1/audit` | audit-service |
| 100 | `/api/v1/codebook` | codebook-service |
| 100 | `/api/v1/policy` | policy-service |
| 100 | `/api/v1/ai` | ai-service |
| 100 | `/api/v1/tender` | tender-service |
| 100 | `/api/v1/thinktank` | thinktank-service（请求体上限 `thinktank-limit` 50MB+256KB，其余前缀 `request-limit` 20MB+256KB） |
| 110 | `/api/v1/ai/stream` | ai-service（不挂压缩和请求缓冲，流式回答逐段下发） |
| 110 | `/api/v1/ai/batch-runs/{id}/files/{kind}` | ai-service（批量产物下载，不压缩不缓冲） |
| 110 | `/api/v1/thinktank/knowledge/{id}/content`、`/download` | thinktank-service（知识文件流式下发，不压缩不缓冲） |
| 50 | `/api/v1` 兜底 | api-fallback（统一 JSON 404） |
| 1 | `/` 兜底 | frontend（SPA） |

`/health/*`、`/internal/*` 不声明路由，对外不可达。

## 5. 前端构建的坑

- pnpm 12 读 `pnpm-workspace.yaml` 的 `allowBuilds`，不再读 `package.json` 的 `"pnpm"` 字段。
  Dockerfile 必须先 `COPY` 该文件再 `pnpm install`，且装同一版本 pnpm（`npm install -g pnpm@12.4.1`），
  否则旧版会报误导性的 `packages field missing or empty`。
- 不用 `corepack prepare`：Node 22 镜像上签名校验失败（`Cannot find matching keyid`）。
- `@vue/tsconfig` 没有 `tsconfig.node.json`，`frontend/tsconfig.node.json` 继承 `@vue/tsconfig/tsconfig.json`。
- 根 `.dockerignore` 排除 `**/node_modules/`、`frontend/dist/`，避免宿主机依赖拷进镜像。
- Element Plus 整包引入，`element-plus-*.js` 约 1MB（gzip 约 320KB），构建会提示超 500KB，目前接受。

## 6. 统一响应与异常

`platform_common` 的 `responses.py` / `errors.py` 按架构文档 11.1 节：
`{"code": "OK", "message": "success", "data": ..., "request_id": "..."}`。
统一处理 `ApiError`、`RequestValidationError`（422）、`StarletteHTTPException`、未捕获异常（500，不泄露堆栈）。
`X-Request-Id` 与响应体 `request_id` 同值。`ApiResponse[T]` / `Page[T]` 用 PEP 695 泛型语法。

## 7. Alembic 与配置解耦

`platform_common/orm_base.py` 只放 `DeclarativeBase`。各服务 `migrations/env.py` 只导入它和本服务的 model 模块
（注册元数据），不导入 `app.core.config`，执行迁移时不需要 Redis 等无关配置。连接串从各服务 `*_DATABASE_URL` 环境变量读取，不写进 `alembic.ini`。
历史迁移不能 import 运行时 model，见 `CLAUDE.md`「ORM 中文 comment」。

## 8. 认证与会话

- JWT RS256，Access Token 8 小时；Refresh / 会话 7 天，旧 Refresh Token 有 30 秒重用宽限，
  超过宽限即撤销整个会话族，且这次撤销先提交，不被请求结束时的回滚抹掉。
  JWT 只带 `sub/sid/iss/aud/iat/exp/jti` 和头部 `kid`，不带权限树。
- 密钥在 `deploy/secrets/jwt`（gitignore），挂载为 `/secrets/jwt`；生产缺密钥拒绝启动。
  私钥属主须与容器 appuser 同为 uid 1000。
- Refresh Cookie `HttpOnly`、`Path=/api/v1/auth`、`SameSite=strict`，HTTPS 环境 `Secure`。
  CSRF 双提交（可读 Cookie + `X-CSRF-Token`），页面重载先 `GET /auth/csrf` 再 `POST /auth/refresh`。
- 登录失败限流：按账号 5 次、按 IP 20 次 / 300 秒；Redis 异常返回 503，不降级放行。
- 失败登录的 Outbox 用独立会话提交，避免被登录事务回滚。
- 初始管理员密码只经环境变量 `ADMIN_PASSWORD` 传入。服务端生成的口令只在当次响应的
  `temporary_password` 返回一次，日志脱敏键包含该字段。
- 前端 Access Token 只放内存；同页并发 401 共用一个 refresh，跨标签页用 `navigator.locks`
  只让一个标签页消费 Refresh Token，再经 BroadcastChannel 分发。

## 9. 权限引擎

- 业务服务经 `platform_common.authz.AuthzClient` 调 iam `POST /internal/v1/authorize`；IAM 自身接口走本地组件。
- 一次判定两条查询：会话连账号一条，这个人在该模块上的档位一条。资源和动作目录是部署时 seed 的静态数据，
  在 iam-service 进程里缓存 60 秒（查不到的编码立即重读，5 秒内最多一次）；seed 在另一个进程跑，
  下线、取消发布最多一分钟后在判定里生效，要立即生效就重启 iam-service。用户的角色、单独授权不缓存，撤销下一次请求就生效。
- 内部凭据 `IAM_INTERNAL_CALLER_SECRETS`（`服务名 -> 密钥`），请求头 `X-Internal-Service` / `X-Internal-Token`。
- 已授权等级 READ / EXPORT / FULL，没有记录即 NONE；多角色取最高档，停用角色不参与。
- 未发布资源、目录节点、未知动作一律拒绝，超级管理员也不例外。
- `system.permissions` 只能授给内置 `superadmin`。写接口用 Pydantic `extra=forbid`，不能借额外字段改角色或内置标记。
- 最后一个超级管理员保护：事务内锁住全部超级管理员用户行后再数可登录人数。

## 10. 审计投递

- iam-worker 与 iam-service 共用镜像；`data` 网络是 internal，运行时不能 `uv run` 拉依赖，
  worker 命令固定 `.venv/bin/python -m app.worker`。
- policy / codebook / ai / thinktank 的审计不靠独立 worker：服务 `main.py` 的 lifespan 里起 `outbox_loop` 后台任务投递。
- tender-service 没有库和 Outbox：导出、查看正文时同步调审计服务，上报失败回 503，不放出没留痕的数据。
- 写审计用 `AUDIT_INTERNAL_CALLER_SECRETS` 中各服务的密钥；审计查询鉴权用 `AUDIT_IAM_SERVICE_SECRET` 反向调 IAM。
- 认领后 `attempts += 1`，HTTP 在认领事务外发；回写 delivered/failed/dead 前确认 `lease_until`
  仍是本次租约。租约：IAM 30 秒，policy / codebook / ai / thinktank 公共 Outbox 5 分钟。
- `dead` 不自动丢弃，`make outbox-replay` 重置为 pending 并清零 attempts。
- 指标：worker 周期打 `outbox_metrics` 日志；IAM `GET /internal/v1/outbox/metrics`。建议告警
  `dead_count > 0`、`oldest_unfinished_age_seconds > 600`、`failed_count` 持续上升。
- `event_type` 映射为 `module_code/action_code/summary`，未知类型落 `module_code=iam`；payload 投递前脱敏。

## 11. P6 隔离验收

- 在开发部署机上跑：`bash scripts/p6-on-server.sh`，同步源码后跑集成 + e2e，结束一定 `p6-down`。
  服务器资源充足、架构与线上一致（x86），Mac 不必开 Docker；`make check` / `make test-unit` 仍在 Mac 上跑。
- 隔离：Compose 项目名 `tx-zhongtai-p6`、独立网络与卷、`*_p6_db` 库；网关和 Postgres 只绑 `127.0.0.1`，
  因为 P6 账号密码是仓库里的明文样例。备份/恢复脚本拒绝非 `*_p6_db` / `*_itest` / `*_test` 库名。
- Compose 不能把 JSON 默认值写成 `${VAR:-{"k":"v"}}`（插值在第一个 `}` 处结束），P6 覆盖文件用 YAML 单引号字面量。
- 恢复隔离库后要重新 GRANT，并把 public 下表和序列属主改回应用账号，否则 `permission denied for table`。
- OpenAPI 由本地导入 FastAPI 应用导出（`scripts/export_openapi.py`），不依赖 `docker exec`。
