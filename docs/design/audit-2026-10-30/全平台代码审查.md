## 三、建议

- AI：轮与轮之间点停止收尾成「完成」；进度协程在提交后被取消约 2 秒花费记两次；账单把没花钱的任务算 1 次；OOM 后「重跑失败 N 条」偏大；认领到本进程在跑的任务跳过时不回退状态；重跑后排队显示上次的轮次；换样本后「试发这一行」的对照结论不对；前后端模板变量正则不一致。
- 打标：往回重扫时内容重复被跳过的政策每次重付费；连续问不到 ai-service 时后续花费不进「今日已花」。
- IAM：权限目录「动作」查不到不立即重读。
- 政策与码表：同步新增场景失败数最多显示 50；补码文件两列区县编码写错列；配置明细缺栏目名列；10-22 当天建的规则被算成期初。
- 工程：Postgres 超级用户口令不在示例密钥检查范围；大表建索引必须 CONCURRENTLY 的检查可被绕过。

## 四、处理结果

### 第一批：严重 3 条和数据、停摆类

- S1：展开时按规则 ID 也取一遍已对上的行，改了编码的不再展开第二次；批次记 `moved`，调度页写出条数，预览 Excel 列出来。
- S2：失败与拒绝留痕、在线用户的最近活跃改用单独的小连接池（`database.SideSessionLocal`，2+3 条、等 0.5 秒），拿不到就放弃；登录失败留痕写不进去时照样回 401。
- S3：类型和「是否解读」都没变时，只换类型那步的说明，解读和市场机会的失败说明留着；判成重复副本的同理。
  顺带修了同一处：重新判断类型这次没问成（网络、限流）原来会把类型清空、「是否解读」改成否、删掉没人核对过的 AI 解读；现在保留上次的结果，只记失败说明并出队。
- T1：内部调用的 JSON 按 UTF-8 发；`/internal/v1/pipeline-runs` 单独 64MB 上限；政策服务每批只发 56MB 以内的行，其余记成未执行、下一批接着做。
- T2：「政策原文名称」限 500 字：页面和导入超长提示，AI 写解读时截断（不删索引，列表默认排序要用）。
- C1、C2、C3：展开结果带上同网页清单；已有栏目行的规则先占网页、规则 ID 按数字排；对上已有栏目行时上线时间只往前对齐、不往后挪（和按网站一行同一口径）。C6 的撞号条数也记进批次、在调度页显示。
- A1：旧系统导入跳过新系统里删过的任务。A2：下载只发请求开始时的长度。
- C4、C5（第一批部署时一起上）：信源列表、导出排序以 ID 兜底；导入允许同一网站（名称、省、市都一样）共用网站编码，不同网站撞编码才拒收。
- O1（同上）：P6 覆盖文件给 audit-worker 补上内部密钥；验收加一项 A16，四个 worker 都在跑、没有容器在反复重启。

### 第三批：建议

  任务记「还没答好的行数」（`open_count`），重跑条数不再偏大，重跑排队时轮次从 1 算起；认领时排除本进程还在跑的任务；
