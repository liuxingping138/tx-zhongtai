# 招中标模块

`tender-service`（8006）读取外部 MySQL，接入 IAM 和 Traefik，不需要新建 PostgreSQL 库、迁移或 worker 容器。

## 只读边界

用户明确禁止写入、修改、删除这些源表。本服务只有 GET 业务接口；执行器只接受单条 SELECT，无迁移、导入、回传、建索引能力。部署使用仅有所需表 SELECT 权限的数据库账号。程序不会自动创建或修改账号权限。

| 数据视图 | 招标 | 中标 |
| --- | --- | --- |
| 原始数据，状态 0 | bid_analyse.bid_purchaser_info_dis_pro | bid_analyse.bid_winbid_info_dis_pro |
| 人工已处理，状态 1 | bid_analyse.bid_purchaser_info_dis_approval_pro | bid_analyse.bid_winbid_info_dis_approval_pro |

列表按所选状态切表，同时按 `project_status` 过滤。字段来自根目录 `展示字段.xlsx`，另显示状态、场景标记、采集和入库时间；项目 ID 是 `project_content_id`，内部主键 `id` 只用于查详情且转为字符串，避免 JS 数字精度丢失。

## 统计口径

- 总量统计原始表全部记录，不能累加交付表造成重复。
- 每日接入、省份分布按原始表 `collect_date` 聚合；省份是 `purchaser_provname`，空值显示「未填写省份」。
- 每日人工信息化标签量、基础字段补充量均为当日采集数据中 `project_status='1'` 的记录数，两项数值相同且不相加；场景处理固定 0。
- 这是用户确认的采集日期归属口径，并非实际上传时间审计。原始表后续回传状态变化，会改变历史日期的处理量。
- 默认近 7 天，单次最多 31 天；按天等值查询以便分片路由。无数据日期补 0。
- 统计和精确计数缓存 5 分钟，只在内存中保存。重启后重新计算，不伪造总量或用估算代替。
- 全表总量使用独立后台线程，服务启动后预热，每 30 秒检查缓存；刷新期间或失败时保留最近一次成功结果及其统计时间。筛选精确计数通过最多 2 个后台线程、最多 8 个排队或运行任务完成。GET `/statistics/totals` 和 `/{kind}/count` 返回 pending / ready / error 状态，前端每 3 秒轮询，离开页面停止。错误会显示，列表仍可用。计数缓存最多 128 项；超时默认单次 120 秒。
- 列表分页不依赖 COUNT，默认 20 条，取多一条判定是否有下一页。交付数据及带条件查询按 `public_date DESC, purchaser_provname DESC, id DESC` 倒序，原始表全量无过滤查询按 `public_date DESC, id DESC` 倒序；筛选有采集/发布/入库日期闭区间和名称关键词等，发布/入库时间的结束日转换为次日开区间，不截断当天时间。采集日期为 YYYY-MM-DD，起止齐全且跨度不超过 366 天时用单日等值或逐日 IN，避免代理范围扫描；更宽或无界查询仍可能较慢。

## 正文

列表不读取 content。详情点击加载时才查询：

1. 交付记录先按 `project_content_id` 找回原始表的 `collect_date`。
2. ID 长度 <=13：数字 ID 用 `qlm_saas_content.infoid` 查询 `infocontent`。
3. ID 长度 >13：用 `crawler2021.zhaobiao2021_prod.uid` 查询 `content`，同时带 `create_time = collect_date`。
4. 找不到正文记录与关联记录正文为空分别提示，不回退到无日期的全表扫描。

HTML 保留原文结构，通过 `sandbox=""` iframe 与 CSP 展示，脚本、外部请求、表单和同源访问被隔离。正文中的外链图片不自动加载。

## 部署

遵循 [部署与维护](部署与维护.md) 的同步与构建流程，本次开发不自动修改运行中的服务或数据库权限。

1. 服务器 `.env` 配置 `TENDER_MYSQL_HOST / PORT / USER / PASSWORD`，指定只有 SELECT 权限的账号。
2. 配置 `TENDER_IAM_SERVICE_SECRET`，将同一值以 `"tender-service":"..."` 合并到 `IAM_INTERNAL_CALLER_SECRETS`，保留已有调用方。不要用示例密钥。
3. 按现有发布流程构建并启动 `tender-service`、`iam-service`、`frontend`，更新网关动态配置。
4. 执行 IAM 的 `python -m app.cli.seed` 同步资源与菜单，按业务角色授权：`tender.statistics`、`tender.purchaser`、`tender.winbid`。三个资源只有只读动作。
5. 检查 `/health/ready` 和三个页面。未配数据源时接口明确返回 503，不显示虚假空数据。

无需修改四张业务表或两张正文表，无需 Alembic 迁移。
