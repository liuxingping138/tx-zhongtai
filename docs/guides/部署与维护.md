## 备份与恢复

备份覆盖四个服务库：`iam` / `audit` / `policy` / `codebook`。每个库一份 `<服务>.dump` 加一份记录库名的 `<服务>.dbname`。

脚本只允许库名匹配 `*_p6_db` / `*_itest` / `*_test`，拒绝开发库（`iam_db` / `audit_db` / `policy_db` / `codebook_db`），并要求 `RESTORE_CONFIRM` 等于目标库名。

```bash
make p6-backup
RESTORE_CONFIRM=iam_p6_db make p6-restore BACKUP=deploy/backups/<stamp>
```

恢复要求备份目录四个库齐全，缺任何一个直接拒绝——否则会恢复出「框架库回到备份点、业务库还是现场数据」的混合状态。2026-09 之前的备份只有 `iam` / `audit`，不能用新脚本恢复。

`pg_restore --no-owner` 之后，脚本会把当前库 public 里的表、序列和函数属主改回应用账号，再补 GRANT。只做 GRANT 时，后面的迁移仍可能因为不是属主而失败。恢复是否成功，要看到应用账号能执行下一次迁移，不能只数行数。

业务四库不走上面的隔离恢复入口。只读导出：

```bash
CONFIRM_BUSINESS_BACKUP=yes BACKUP_COMPOSE="$DC" BACKUP_ENV_FILE=.env bash scripts/backup_business.sh
```

备份默认写到运行用户家目录的 `tx-zhongtai-backups/<时间>/`。这个脚本不会把备份灌回 `iam_db` 等业务库。要演练恢复，先导入临时库或隔离库，确认应用账号能迁移，再由人工决定是否切换。现有隔离库白名单保持不变。

Redis 丢失不影响已经落库的授权。会话限流计数会清空。

## HTTPS

服务器没有域名，按访问地址申请 Let's Encrypt 的短期 IP 证书，有效期约 6 天，必须自动续期。宿主机 80 和 8080 已被其他项目占用，不要把网关绑到这两个端口，也不要改那些站点的配置。只在现有 Nginx 上增加 `/.well-known/acme-challenge/` 的目录映射。

```bash
# 在服务器上。PUBLIC_IP 填浏览器地址栏里的主机地址，ACME_WEBROOT 填 Nginx 已对外提供的校验目录。
PUBLIC_IP=... ACME_WEBROOT=/var/www/acme ACME_EMAIL=... bash scripts/renew_ip_cert.sh
```

证书写到 `deploy/secrets/tls/`，该目录不进 Git。然后在原有 Compose 上叠加 HTTPS 文件。8091 仍接收 HTTP，并跳到 `https://<地址>`。叠加之后刷新 Cookie 带 Secure。

```bash
DC="sudo docker-compose -f deploy/compose/docker-compose.yml -f deploy/compose/docker-compose.https.yml --env-file .env"
$DC up -d gateway iam-service
```

续期由 `tx-zhongtai-cert-renew.timer` 每天两次调用同一个脚本。脚本更新证书并原子替换动态配置，触发 Traefik 重新加载。证书文件还没放好时不要叠加 `docker-compose.https.yml`，否则网关起不来。

放行 443 时只加这一条防火墙规则，不要改其他项目的端口。PostgreSQL 的 5433 维持现状。

## 已知限制

- 单机 Compose 不是高可用。
- 表属主账号在 PostgreSQL 中可能仍显示部分属主级权限（如 TRUNCATE），应用连接未使用删除/更新历史审计。
- Playwright 与集成测试只打隔离栈，不清开发库。

## 网关响应压缩

`deploy/gateway/dynamic.yml` 的 `compress` 中间件挂在全部路由上。
JSON 与前端资源都是高压缩比文本，实测：

| 响应 | 未压缩 | gzip | 节省 |
| --- | --- | --- | --- |
| `/policy/sources/options` | 962KB | 134KB | 86% |
| `/codebook/scenarios/options` | 107KB | 21KB | 80% |
| 列表首屏 20 条 | 12KB | 2.5KB | 79% |
| 前端主包 | 1.14MB | 392KB | 66% |

xlsx、zip、图片等本身已压缩的类型在 `excludedContentTypes` 里排除，
再压一次没有收益，只会白白消耗两端 CPU。Traefik 默认只压缩超过 1KB 的响应。

## 会话与刷新令牌清理

`iam_sessions` 和 `iam_refresh_tokens` 只增不减：每次登录写一行会话，
每次刷新写一行令牌。没有清理任务时会一直涨（开发环境几天就 300+ 行）。

```bash
make iam-session-cleanup
```

- 只删**已过期**或**已撤销**、且再往前推 `IAM_SESSION_RETENTION_DAYS`
  （默认 30 天）的记录；在用会话和最近失效的会话都不动。
- 先删令牌再删会话：`iam_refresh_tokens.session_id` 是
  ON DELETE RESTRICT，顺序反了会被外键挡住。
- 建议按月执行；执行后日志会打印删除数与剩余数，便于观察增长趋势。

在一次性探测库上用受控夹具验证过：40 天前过期、40 天前撤销的两个会话
及其 4 个令牌被删除；在用会话和 2 天前刚过期的会话保留；无孤儿令牌。

## 客户端 IP 的信任前提

登录限流和审计留痕里的来源 IP 取自 `X-Forwarded-For` 的第一段，
由网关写入。Traefik 默认丢弃客户端自带的 `X-Forwarded-*` 再重写
（已实测：伪造 `X-Forwarded-For: 203.0.113.99` 不会进入服务）。

由此带来两条部署约束：

- 各服务端口（8001–8004）**不得**直接对外暴露，只能经网关访问。
- 不要在 Traefik 前面再加一层不做同样清洗的代理。

任一条被打破，攻击者就能自行构造该头，绕过按 IP 的登录限流，
并在审计日志里伪造来源 IP。按账号维度的限流不受影响，仍然生效。

## 2026-10 修复后的发布与备份约定

- HTTPS 使用宿主机 **443**，8091 重定向到 443；8443 为其他项目占用。HTTPS overlay 固定映射 `443:443`，修改端口必须同时修改静态入口和跳转目标，不能只改宿主机映射。HTTP 原站的 80 不改。
- IP 证书使用 Certbot 5.4.0 容器和现有站点 webroot，每天两次运行 `scripts/renew_ip_cert.sh`。脚本将证书写入 TLS 目录并原子替换动态配置，触发网关重载。依据：[Let's Encrypt 的 IP 证书说明](https://letsencrypt.org/2026/03/11/shorter-certs-certbot)。每次发布需验证证书 IP SAN、有效期、HTTPS 页面/CSRF、8091 的 Location；续期用 `certbot renew --dry-run` 在 staging 验证。
- 网关总请求上限为 21233664 字节（20MiB 加 256KiB multipart 开销）。服务 `IMPORT_MAX_BYTES` 若调大，需要同步调整两份 dynamic 配置；仅改服务参数不会提升公网限额。
- 本次按用户要求仅备份一次，因此没有周期性 RPO 承诺。恢复演练目标 RTO 2 小时；实际演练记录见本次发布报告。四库串行快照不承诺跨库同一时刻，需要严格共同恢复点时先停止本项目写入及 worker，再备份。
- 本次一次性备份已在验证完成后按用户要求删除，没有备份或清理定时任务。手动再次运行备份脚本时默认清理超过 14 天的完整备份。`BACKUP_ROOT` 指定目录；`BACKUP_RETENTION_DAYS` 调整保留天数。脚本先写临时目录，四库导出和归档检查全成功后生成 SHA256SUMS/COMPLETE 并原子发布。失败返回非零，不删除旧备份。
- 异机备份：设置 `BACKUP_OFFSITE=备份用户@备份主机:/专用目录`，预先配置受限 SSH 密钥、known_hosts 和目录权限；脚本 rsync 成功才写 OFFSITE_SENT。异机目标建议保留 30 天；服务端应设置独立的保留/版本策略，不能依赖源服务器删除策略。未配置目标时仅代表本机备份，不能宣称自动异机保障。
- 恢复演练必须在隔离实例/库执行：校验 `sha256sum -c SHA256SUMS`，将备份导入 `*_p6_db` 等允许库，恢复应用 owner，使用应用账号运行 `alembic upgrade head`、`alembic check` 和下一次临时迁移，并验证数据及登录。业务备份 `.dbname` 记录业务库名，禁止为了绕过保护直接在原恢复脚本中放宽白名单；演练应复制到独立目录，审阅目标映射后只修改该副本的 `.dbname`。
- 本次未安装备份 systemd service/timer。手动备份失败以脚本非零退出码和终端输出为准；验证目录 COMPLETE、SHA256SUMS 后方可将其当作完整恢复点。
