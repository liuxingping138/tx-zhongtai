# 配置说明

真实密钥只放在本机 `.env` 或密钥目录，不提交仓库。`.env.example` 只提供字段清单和演示值。

## 环境标识

| 值 | 用途 |
| --- | --- |
| `development` | 本地 Compose / `pnpm dev` |
| `test` | 隔离验收栈（P6） |
| `production` | 生产模板；演示密钥会被拒绝启动 |

各服务环境变量前缀：IAM 用 `IAM_`，审计用 `AUDIT_`，码表用 `CODEBOOK_`，政策用 `POLICY_`。

## 必填项

| 变量 | 说明 |
| --- | --- |
| `POSTGRES_SUPERUSER` / `POSTGRES_SUPERUSER_PASSWORD` | 仅初始化脚本用，应用不使用 |
| `IAM_DB_*` / `AUDIT_DB_*` / `CODEBOOK_DB_*` / `POLICY_DB_*` | 各自独立库与账号 |
| `AUDIT_CLEANUP_DB_USER` / `AUDIT_CLEANUP_DB_PASSWORD` | 到期清理专用账号 |
| `IAM_INTERNAL_CALLER_SECRETS` | 调用 IAM 内部接口的服务名→密钥 |
| `IAM_AUDIT_INGEST_SECRET` | Worker 写审计的内部密钥 |
| `AUDIT_INTERNAL_CALLER_SECRETS` | 允许写审计的服务名→密钥 |
| `AUDIT_IAM_SERVICE_SECRET` | 审计查询时调 IAM 授权的密钥 |

JWT 私钥目录：`deploy/secrets/jwt`（gitignore）。`make bootstrap` / `make jwt-keys` 会生成开发密钥。

## 会话与安全默认值

- Access Token 8 小时，Refresh / 会话 7 天，算法 RS256。短时间重复刷新不再撤销会话。
- Refresh Cookie：`HttpOnly`，`Path=/api/v1/auth`，`SameSite=strict`。
- 登录失败按两个维度限流，窗口都是 300 秒：同一账号 5 次（`IAM_LOGIN_MAX_FAILURES`，用户名去空格、转小写后计数），
  同一 IP 20 次（`IAM_LOGIN_MAX_FAILURES_PER_IP`，登录成功不清零）。Redis 不可用时登录返回 503。
- 审计默认保留 180 天，由 `AUDIT_RETENTION_DAYS` 调整。
- 会话/刷新令牌失效后默认再留 30 天，由 `IAM_SESSION_RETENTION_DAYS` 调整，`make iam-session-cleanup` 执行清理。

## 筛选项候选值

七个列表页（六张业务表 + 操作日志）统一走同一套机制。

`GET <业务前缀>/options` 每个字段最多返回 200 个候选，超出则标 `truncated`；
前端对被截断的字段改调 `GET <业务前缀>/options/search?field=&q=`（每次最多 50 条）。

历史实现一次性下发全部去重值、上限 8000，既让信源的网站名称（1 万多个不同值）
排序靠后的部分永远搜不到，也让单次响应接近 1MB。上限常量在
`platform_common/options.py` 的 `PREVIEW_LIMIT` / `SEARCH_LIMIT`。

## 导入导出限制

policy-service 与 codebook-service 各自生效，环境变量前缀分别是 `POLICY_` / `CODEBOOK_`。

| 配置 | 默认 | 说明 |
| --- | --- | --- |
| `*_IMPORT_MAX_BYTES` | 20MB | 上传文件体积上限，分块读取，超限立刻返回 422 |
| `*_EXPORT_MAX_ROWS` | 100000 | 单次导出行数上限。导出是整表读进内存再生成 Excel，超限返回 422 并提示联系管理员 |

导出接受与列表完全相同的筛选参数，超限时先缩小筛选范围即可，不必直接调高上限。

## 爬虫监测数据源

只有同步 CLI 连爬虫库，服务进程不连；页面只读本服务库里聚合好的表。

| 变量 | 说明 |
| --- | --- |
| `POLICY_CRAWLER_MYSQL_HOST` / `_PORT` / `_USER` / `_PASSWORD` / `_DB` | 爬虫库连接，建议单独建**只读账号**，不要用 root |
| `POLICY_CRAWLER_SYNC_DAYS` | 首次尚无水位时的回算天数，默认 7。日常按入库时间水位识别受影响日期；`--days N` 明确强制回算固定区间，不推进水位 |
| `POLICY_CRAWLER_HEALTH_NORMAL_DAYS` / `_WATCH_DAYS` | 健康分档阈值，默认 7 / 30。停更 ≤7 天正常，≤30 天观察，其余断爬 |

```bash
make crawler-sync                              # 日常增量
make crawler-backfill DAYS=365                 # 按天数回填
# 首次回填必须覆盖到爬虫库最早的采集日期，否则窗口外停更的任务会被误判成「从未出数」
docker compose ... exec -T policy-service .venv/bin/python -m app.cli.sync_crawler --since 2023-10-18
# 长回填中断后续跑，跳过已入库的日期
... --since 2023-10-18 --skip-existing
```

已接入系统管理 → 任务调度，独立 `policy-worker` 每天执行两套增量同步，默认北京时间 10:00 / 10:10，可在页面调整。不要再配置重复的宿主机 cron。详见 [任务调度](任务调度.md)。

### 爬虫监测 v2

v2 只读采集总表 `csys_policy_info_source_all`，按「网站名称 + 省份 + 地市」的原始值统计（不做别名归一），
不读规则表。它和 v1 并存，表、水位、同步命令、菜单权限都各自独立。连接变量与健康阈值沿用上表，
状态分档：停更 ≤7 天正常，≤30 天关注，其余停更；停更天数按最新入库日期计算。

```bash
make crawler-v2-backfill                        # 首次：从总表最早采集日回填到今天，并建立水位（约 45 分钟）
make crawler-v2-backfill ARGS=--skip-existing   # 回填中断后续跑，沿用中断批次的水位
make crawler-v2-sync                            # 日常：按入库时间水位增量重算受影响的采集日
docker compose ... exec -T policy-service .venv/bin/python -m app.cli.sync_crawler_v2 --days 30   # 修复：固定重算，不动水位
```

- 没有成功回填过时，日常同步会直接报错提示先回填，不会用短窗口算出偏小的数据总量。
- 新环境如果是整库迁移 `policy_db` 过去的（含 `policy_crawler_v2_sync_runs` 里的水位），**不需要再回填**：
  确认能连上同一个爬虫库后直接 `make crawler-v2-sync`，会从库里的水位接着把迁移期间新入库的数据补上。
  只有空库部署才需要 `make crawler-v2-backfill`。
- 已删除数据（`status='-1'`）不计入。爬虫方把旧数据标记删除不会改 `create_time`，日常增量感知不到，
  需要时用 `--days` 做一次修复性重算。
- 同步进程被杀或容器重启时，页面会提示「同步意外中断」，重新执行同步即可。
- 两套并存期间每天各跑一遍（`make crawler-sync` 与 `make crawler-v2-sync`）。v2 核对无误后再单独下线 v1。

## 端口（本地）

| 用途 | 开发默认 | P6 隔离栈 |
| --- | --- | --- |
| 网关 | `GATEWAY_HTTP_PORT=8080` | `8090` |
| PostgreSQL 宿主机映射 | `5433` | `5434` |
| Redis 宿主机映射 | `6380` | `6381` |

服务端口、数据库、Redis 不得对公网暴露。生产只公开网关 443，见 `deploy/gateway/traefik.prod.yml.example`。

## 隔离验收栈

`deploy/compose/p6.env.example` → `deploy/compose/.p6.env`。库名必须是 `*_p6_db`，避免备份/恢复误伤开发库。

内部 JSON 密钥在 Compose 里写成 YAML 单引号字面量。不要写 `${VAR:-{"k":"v"}}`：Compose 会把第一个 `}` 当成插值结束，容器里只剩 `{`，服务无法启动。

## 爬虫监测身份升级

从 `f3a9b0c1d209` 起，统一按“网站名称 + 标签”关联规则与采集量。原始网站编码继续展示，但不作为正常网站的关联条件；名称为空时才以编码兜底。旧版按空编码聚合已经丢失网站边界，不能直接换键恢复。迁移保留旧聚合并标记为未校验，页面提示历史需要重新同步；新安装空库不受影响。

旧环境升级需先备份，再使用当前源码重建政策服务镜像，执行迁移，并从爬虫库最早日期完整回填。禁止用旧容器执行新表结构的同步。回填完成前页面会持续提示统计不完整。

```bash
docker compose -f deploy/compose/docker-compose.yml --env-file .env build policy-service frontend
docker compose -f deploy/compose/docker-compose.yml --env-file .env stop policy-service
docker compose -f deploy/compose/docker-compose.yml --env-file .env run --rm --no-deps policy-service .venv/bin/alembic upgrade head
docker compose -f deploy/compose/docker-compose.yml --env-file .env up -d --no-deps --no-build policy-service frontend
docker compose -f deploy/compose/docker-compose.yml --env-file .env exec -T policy-service .venv/bin/python -m app.cli.sync_crawler --since 2023-10-18
# 完整回填成功后再执行一次日常增量，补齐回填过程中继续入库的数据
docker compose -f deploy/compose/docker-compose.yml --env-file .env exec -T policy-service .venv/bin/python -m app.cli.sync_crawler
```

同步持有 PostgreSQL 会话级锁，禁止并发回填交错覆盖。完整规则快照会移除已删除规则；每天的聚合按事务替换，源端清空某天也会清除对应旧分组。水位探测失败会记录失败批次；`--tasks-only` 不读取采集大表。所有自然日计算使用北京时间，MySQL 无时区入库时间按北京时间解释，水位以 UTC 存储。

源端瞬时连接故障最多尝试三次，重试前重新连接；认证和 SQL 错误不重试。长回填中断可使用原日期范围加 `--skip-existing` 续跑，仅跳过已经按网站名称校验的日期，迁移前的旧聚合不会被误判为已完成。迁移失败时应先核对事务回滚状态，再恢复旧容器；新旧镜像与数据库版本必须配套。

容器启动直接运行镜像构建阶段已安装的 `.venv/bin/uvicorn`；迁移和同步使用 `.venv/bin/alembic` / `.venv/bin/python`，不在运行时重新联网解析或安装依赖。
