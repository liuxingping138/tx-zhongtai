## 已修复问题

| 优先级 | 问题及影响 | 修改 |
| --- | --- | --- |
| P1 | 缺少网站编码的不同网站被合并，同名网站在规则和数据中编码不同又会拆开 | 规则、日统计和健康快照统一使用名称生成的内部关联键；按名称和标签聚合 |
| P1 | 列表把中文健康状态转换为 API 枚举，导出未转换，导致下载为空 | 列表和两类导出共用转换，导出采用已生效筛选；API 拒绝非法状态 |
| P1 | 规则删除、源数据当天变空或改标签后，旧任务和分组一直保留 | 完整规则快照、每日统计事务替换；清理无规则且无统计的健康记录 |
| P1 | 新数据库迁移失败：旧注释迁移引用最新模型，对尚不存在的表执行注释 | 冻结历史迁移的表和列清单，不再运行时引用当前 metadata |
| P1 | 容器启动执行 uv run，在新运行用户下尝试下载构建依赖，离线启动失败 | 四个后端服务直接运行镜像内已经安装的 .venv；Make 容器内命令同样调整 |
| P2 | 趋势图缺少零采集日，断爬区间被压缩、末尾停更天数消失 | 固定返回完整日期序列，补零至北京时间当天；响应式坐标刻度 |
| P2 | 水位探测阶段失败没有同步记录，失败时间被展示为数据更新时间 | 先建立同步批次，再探测源端；失败留痕；更新时间采用最后成功批次；展示持久状态提示 |
| P2 | UTC 日期造成北京时间凌晨“昨日”口径错误；MySQL 无时区水位偏移 | 自然日统一北京时间，水位存 UTC；修正旧水位 |
| P2 | 显式 --days 仍按水位运行，与命令语义不符；并发回填可相互覆盖 | 显式日期范围强制回算；会话级 PostgreSQL 锁阻止同时同步 |
| P2 | 历史缓存无法无损恢复网站边界，断点续跑可能误跳过未校验日期 | 保留原聚合并标记待回填；新统计只纳入校验过的数据；续跑只跳过已校验日期 |
| P2 | 筛选选项接口未按公共组件约定包装，所有下拉候选为空 | 返回统一 options 结构；补契约回归；健康状态限制为合法候选 |
| P2 | 服务恢复后只重试列表，筛选候选仍为空 | 重试统一恢复列表、概览和筛选项；服务错误提示明确下一步 |
| P2 | 窄窗口列设置弹层超出下边界，全选按钮不可见 | 弹层避让视口边界，内容区限高、内部滚动 |
| P2 | 概览挤占固定页面高度，列表仅剩两三行；健康状态区域阅读松散 | 自然页面滚动和响应式表格高度；状态以四行对齐标签、数量、占比和选中反馈 |

完整规则快照中存在无法解析的规则时，本轮同步失败并保留旧基线，避免把解析失败误当成源端删除。

- 登录、首次改密 API、列表 20 + 8 分页、健康状态筛选、重置、按名称筛选无结果、无编码任务详情通过。
