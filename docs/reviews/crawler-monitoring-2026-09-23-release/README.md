## 真实数据验证

### 为什么本次再次完整回填

数据库保留的同步记录证实：2026-09-22 16:01–17:21 已按旧口径完成全历史同步，之后最后一次增量仅覆盖 9 月 21–22 日。本次没有把昨天的成功同步误判为失败。

对保留旧镜像的实际代码检查确认：旧 SQL 按网站编码与标签聚合，并用 `MAX(site_name)` 保留一个名称；无编码的多个网站可被合并。新口径改为网站名称与标签，旧聚合无法可靠拆分，故此次升级重新读取完整历史。它是一次数据身份升级，普通 UI 发布、重启和日常同步不需要重复执行。

日常调用 `make crawler-sync`，按成功水位寻找新增入库数据涉及的日期，并重算当天。规则快照刷新和本地健康汇总重算仍会执行，但不等同于读取全部历史采集数据。人工 `--since` / `--days` 仅用于首次初始化、口径升级或指定范围修复，不应作为每日调度命令。
