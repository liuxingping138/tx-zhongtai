# 开发约定

后续开发必须遵守。本文件只记必须执行的约定，不重复架构背景。

## 1. ORM 表和字段必须写中文 comment

所有业务 `models`（`services/*/app/domain/models.py`）的表、列都必须带**中文 comment**。
PostgreSQL 会落到 `COMMENT ON TABLE / COLUMN`，Navicat 等工具直接显示业务含义。

硬性要求：

- **新建表**：`__table_args__` 必须带 `comment="中文表名"`。有唯一约束时，把 comment 放在 tuple 最后一项字典里。
- **新建列**：每个 `mapped_column(...)` 必须带 `comment="中文列名"`。
- **改列/加列**：同步改 model 的 `comment`，并在 Alembic 迁移里写出 `comment=` 或 `COMMENT ON`。
- 文案用业务中文（与 Excel 表头、页面列名对齐），不要写英文字段名、不要留空。
- `alembic_version` 是迁移版本表，不用加业务注释。

示例：

```python
class Source(Base):
    __tablename__ = "policy_sources"
    __table_args__ = (
        UniqueConstraint("site_code", name="uq_policy_sources_site_code"),
        {"comment": "信源管理"},
    )

    site_name: Mapped[str] = mapped_column(String(255), nullable=False, comment="网站名称")
    site_code: Mapped[str] = mapped_column(String(16), nullable=False, comment="网站编码")
```

只有 `__table_args__` 且没有约束时，可以直接写：

```python
__table_args__ = {"comment": "政策基础标签表"}
```

Alembic 注意：

- `create_table` / `add_column` 必须带上 model 里的中文 `comment`，不要生成无注释的空表。
- PostgreSQL 的 `COMMENT ON ... IS $1` 不能绑参数，存量补注释时用 SQL 字面量。
- 改完 model 后执行对应服务迁移，确认库里能查到 `obj_description` / 列注释。

## 2. 开发栈和 P6 隔离栈分开用

日常开发和 Navicat 只用开发栈；P6 是一次性隔离验收环境，**不要常开**。

| | 开发栈 | P6 隔离栈 |
| --- | --- | --- |
| 启动 | `make dev-up` | `make p6-up` 或 `make test-integration` |
| 停止 | `make dev-down`（保留数据卷） | `make p6-down`（删除隔离卷） |
| 库/端口 | `.env`，Postgres 默认 `127.0.0.1:5433` | 独立项目名、独立库和卷 |
| 数据 | 开发数据，长期保留 | 用完即扔，不影响开发库 |

硬性要求：

- `make dev-up` **不得**顺带启动 P6。
- 验收结束后必须 `make p6-down`，不要让 `tx-zhongtai-p6-*` 跟着 Docker Desktop 一直挂着。
- 不要把开发库连到 P6，也不要用本机 Homebrew 的 `5432`/`6379` 当项目库。
- 项目库和 Redis 在 Docker 里；本机 Postgres/Redis 空闲与否和开发栈无关。

## 3. Excel 导入导出必须放线程池、上传必须边读边限流

`openpyxl` 读写是纯 CPU 同步操作，每个服务只跑一个 uvicorn worker，
直接在协程里调用会把整个服务的事件循环占住，导出期间所有人的请求都被挂起
（实测 5 万行导出阻塞 4.2s、导入阻塞 3.3s）。

- 业务层一律调用 `app/application/excel.py` 里的 `parse_sheet_async` /
  `build_workbook_async` / `encode_skipped_file_async`，不要直接调同步版本。
  同步函数保留给单元测试用。
- 上传入口用 `app/core/http_utils.py` 的 `read_upload_within_limit(file, settings.import_max_bytes)`。
  先 `await file.read()` 再判断长度，会把整个文件读进内存后才拒绝，体积上限就形同虚设。

## 4. 跨服务公共能力放 platform-common

policy 和 codebook 的基础设施代码基本一致，一律下沉到
`packages/platform-common/platform_common/`，服务内只留绑定：

| 能力 | 公共模块 | 服务内保留 |
| --- | --- | --- |
| 时钟、北京时间格式化 | `clock.py` | 无 |
| ORM Base | `orm_base.py` | 无 |
| 安全分级、Outbox 状态枚举 | `enums.py` | 无 |
| 操作者身份 | `actors.py` | 无 |
| 列表/导出筛选类型 | `filters.py` | 无 |
| 上传限流、成功响应、导入结果响应 | `http_utils.py` | 无 |
| Excel 解析与生成 | `excel.py` | 各表列清单 `domain/fields.py` |
| 表头匹配、ColumnSpec、留痕列 | `columns.py` | 同上 |
| Outbox 仓储 | `outbox.py` 的 `OutboxRepository` | 绑定本服务 ORM model |
| 鉴权依赖 | `service_authz.py` | 绑定服务名与 Settings |

新增业务服务时不要复制这些文件，直接引用公共包。
表头匹配一律走 `header_to_field`：它按**最长前缀**匹配，
按列顺序取第一个会把「省份编码」错配成「省份」。

## 5. UI 必须复用本轮规范

新增或调整页面前，阅读 [视觉规范](../DESIGN.md)、[交互契约](../UX-CONTRACT.md) 和 [UI 开发与复用指南](UI开发规范.md)。

- 一列对应一个字段，不在名称下拼接部门、编码、行业等辅助信息。
- 上传、下载放在列表工具栏，不能丢功能或为了留白搬到独立大卡片。
- 宽表默认展示全部数据字段，并提供带文字和数量的列设置：逐列勾选、显示全部列、恢复默认（回到全字段）；操作列贴右侧且不计入数量。
- 列表结果区复用 `ScrollPort` 常显横/纵滑槽；默认每页 20 条时未露出的行必须能上下滚到。
- 账号入口复用 `UserAccountMenu`，放侧栏底部，主行显示名、辅行 `/me.roles`；不要做右上角芯片，不要改登录页。
- 桌面筛选一次展开全部条件；点查询才生效。
- 优先复用 ListPage / FilterBar / ScrollPort / BusinessTable / ColumnPicker / GroupedFields / UserAccountMenu，基础视觉复用 theme.css。
- 修改共享组件或约定，同步 DESIGN.md / UX-CONTRACT.md / UI开发规范.md；历史审查图不是当前规范。
- 交付时确认用户实际访问的端口：5173 是源码热更新；8080 是 Docker 构建产物。更新源码后只刷新8080不会更新页面，需单独重建前端，命令见复用指南。
