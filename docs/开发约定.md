# 开发约定

后续新增表、字段、迁移都必须遵守。本文件只记必须执行的约定，不重复架构背景。

## 1. ORM 表和字段必须写中文 comment

所有业务 `models`（`services/*/app/domain/models.py`）的表、列都必须带**中文 comment**。
PostgreSQL 会落到 `COMMENT ON TABLE / COLUMN`，Navicat 等工具直接显示业务含义。

硬性要求：

- **新建表**：`__table_args__` 必须带 `comment="中文表名"`。有唯一约束时，把 comment 放在 tuple 最后一项字典里。
- **新建列**：每个 `mapped_column(...)` 必须带 `comment="中文列名"`。
- **改列/加列**：同步改 model 的 `comment`，并在 Alembic 迁移里写出 `comment=` 或 `COMMENT ON`。
- 文案用业务中文（与 Excel 表头、页面列名对齐），不要写英文字段名、不要留空。
- `alembic_version` 是迁移版本表，不用加业务注释。

示例：

```python
class Source(Base):
    __tablename__ = "policy_sources"
    __table_args__ = (
        UniqueConstraint("site_code", name="uq_policy_sources_site_code"),
        {"comment": "信源管理"},
    )

    site_name: Mapped[str] = mapped_column(String(255), nullable=False, comment="网站名称")
    site_code: Mapped[str] = mapped_column(String(16), nullable=False, comment="网站编码")
```

只有 `__table_args__` 且没有约束时，可以直接写：

```python
__table_args__ = {"comment": "政策基础标签表"}
```

Alembic 注意：

- `create_table` / `add_column` 必须带上 model 里的中文 `comment`，不要生成无注释的空表。
- PostgreSQL 的 `COMMENT ON ... IS $1` 不能绑参数，存量补注释时用 SQL 字面量。
- 改完 model 后执行对应服务迁移，确认库里能查到 `obj_description` / 列注释。
